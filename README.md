# Gophermart

Накопительная система лояльности с HTTP API, PostgreSQL и фоновой проверкой начислений.

## Запуск

```bash
make local
make run
```

Полный стек в Docker:

```bash
docker compose --env-file .env.dev up --build
```

## Консоль и документация API

После запуска сервис отдаёт две служебные страницы:

| Адрес | Что это |
| --- | --- |
| `/ui` | htmx-консоль для ручного тестирования: формы для всех семи хендлеров, код ответа и тело каждого запроса, живые панели баланса, заказов и списаний |
| `/swagger` | Swagger UI поверх спецификации |
| `/api/openapi.yaml` | сама спецификация OpenAPI 3.0.3 |

Консоль не дублирует бизнес-логику: каждая кнопка выполняет запрос через тот же
роутер `/api/user/*`, что обслуживает внешних клиентов, и показывает настоящий код
ответа. Вход через консоль ставит ту же куку `gophermart_token`, что и обычный
`POST /api/user/login`, поэтому «Try it out» в Swagger UI работает с той же сессией.

Обе страницы подгружают htmx и Swagger UI с jsDelivr по закреплённым версиям и
SRI-хешам, поэтому для их отрисовки нужен доступ в интернет. Сам API от этого
не зависит.

## Команды

```bash
make build-dev
make migrate
make test
make test-ci
```

`make test-ci` считает покрытие по `./internal/...` и требует не менее 80%. В него
входят интеграционные тесты хранилища — им нужна тестовая база из
`docker-compose.test.yml` и переменная `TEST_DATABASE_URI` (значение уже лежит в
`.env.dev`):

```bash
docker compose --env-file .env.dev -f docker-compose.test.yml up -d
make test-ci
```

Без поднятой тестовой базы интеграционные тесты пропускаются и покрытие не дотягивает
до порога.
